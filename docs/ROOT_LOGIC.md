# ROOT_LOGIC.md — логика получения root на iPhone13,1 / iOS 26.2b1: измеренная карта

> Обновлено 24.11.2026. Всё ниже — либо измерено на устройстве (лог `device_log.jsonl`, 129 МБ), либо проверено в образе ядра (`kc_matched.decompressed`, UUID-сматчен с паниками), либо подтверждено первоисточником. Статус: **ROOTSTATE NO**, usable hole не найдена.

## 1. Измеренные примитивы (device, вердикты модулей)

| примитив | вердикт (дословно) | что значит |
|---|---|---|
| Sandbox bad_query escape | `live=36 read=8 write=0 [g=1 flag=0x800000000 part=0 depth=1] root=NO` | **эscape работает, но только ЧТЕНИЕ** (/System, /usr/lib); записи нет |
| worse_query container escape | `0/3 (patched or flags differ)` | публичный «unpatched 26.0–26.7.2» вектор **мёртв** на 26.2b1 |
| bl_sbx: itunesstored | `reachable 0/3` | публичный «arbitrary write as uid 501» **недоступен** |
| daemon pivot: container write | `0 writable targets outside the sandbox` | писать туда, куда читает root-демон, **некуда** |
| task_for_pid root sweep | `0/600 pids openable` | портов root-процессов не получить |
| setuid-root binary scan | `0 root binaries reachable` | setuid-путь закрыт |
| Root-owned file read | `read 2, denied 4` | 2 файла читаются, 4 отказа |
| mach_vm R/W primitives | `WORKING (self)` | r/w работает **только в своём процессе** |
| daemon surface: Mach services | `13/20 services answering` | **единственная живая поверхность** (имена — в логе устройства, нужен прогон) |
| 112477 P4 / unit3 | 12 раундов выжили / паника по команде | паника воспроизводима; контролируемого разыменования нет |

**Вывод по пользовательской плоскости:** все пользовательские пути к root измерены и закрыты, кроме 13 отвечающих Mach-сервисов (кандидаты в пивот — требуют именования прогоном).

## 2. Реверс прошивки (образ ядра, UUID D31DF1C78E876755F1038A1159C7EB0E)

### 2.1 Паника 112477 — полная локализация (VERIFIED)
* Инструкция: `casa x8, x9, [x0+8]` (файл 0x1026418) в **быстром пути `lck_mtx_lock`** (`lock_mtx.c` ~1053); соседний `lck_mtx_destroy` (паника `lock_mtx.c:319`) в сбойном пути не участвует.
* `far = x0 + 8`; `x0` = указатель мьютекса из `[obj+0x148]`; 7 паник: 6× NULL, 1× app-адрес (0x7204459e0).
* Вызывающий: kext IOSurface 393.2.9, функция вставки элемента shared-list (файл 0x32e5838).

### 2.2 Объект — опознан (VERIFIED, 24.11)
* **Замок на +0x148 — статический глобальный мьютекс**: инициализатор VA `0xfffffff0086afef0` (адрес замка `0xfffffff007b653f0`, группа `0xfffffff00ab5e2e0`, тип `LCK_TYPE_MUTEX=0x22`). Конструктор (файл 0x32e1a7c) пишет **один и тот же** указатель в +0x148, +0x238, +0x240, +0x400.
* **Следствие:** NULL/app в `[obj+0x148]` = **сам объект освобождён и переиспользован** (UAF-цель — объект, не замок).
* Объект — **синглтон** (глобал `0xfffffff00acebb88`), поля до +0x458, коллекция на 0x200 (+0x438 = capacity, +0x440 = массив), рост 64-битный (файл 0x32e7c40: `add x23,x24,#0x20` — переаллокация и копирование).
* Семейство объектов shared-list: `IOSurfaceSharedEventListener` (строка имени при инициализации, файл 0x32c6ae0), записи реестра — **24-байтные тегированные объекты** (init файл 0x1760bb0 / release 0x17627e8), глобальный реестр с поиском (файл 0x16aaf04) под глобальным замком `0xfffffff00ab91700`.
* Чтение времени: VA `0xfffffff008171e88` — `mrs s3_4_c15_c10_6` (**CNTPCT_EL0**) + смещение; поля +0x450/+0x458 пишутся один раз и **не читаются** → не вектор 46285.

### 2.3 CVE-2025-46285 (единственный root-class) — состояние
* Публичного разбора/PoC нет (проверено: Apple advisory, NVD, PT Security, SentinelOne — только описание).
* В нашем образе проверенные timestamp-места: expiry-строки уже `%llu` (64-бит), рост коллекции 64-битный, CNTPCT-поля не читаются. **Уязвимое место не локализовано** — слепой поиск 32-битных timestamp без символов и без фиксированного образа для диффа нереалистичен.

## 3. Логические маршруты к root и их измеренный статус

| маршрут | что нужно | статус |
|---|---|---|
| A. Sandbox-escape → root-файлы | запись за пределы контейнера | **закрыт**: write=0, worse_query 0/3, daemon pivot 0 |
| B. uid-501 write → setuid/демон | пишущийся root-путь | **закрыт**: setuid 0, pivot 0 |
| C. task port root-процесса | task_for_pid | **закрыт**: 0/600 |
| D. Mach-сервис пивот | уязвимый сервис из 13 | **открыт как поверхность**, конкретный сервис не опознан (нужен прогон) |
| E. 112477 UAF → controlled deref | канарейка в far | **частично**: паника по команде, объект опознан, канарейки не сели (6/7 NULL) |
| F. 64788 → 65330 (публичная цепочка) | kernel r/w мимо zone sequestration | **заблокировано** (по собственному README PoC); 0x307a в нашем ядре не PAC |
| G. CVE-2025-46285 (root-LPE) | найти уязвимые 32-бит timestamp | **не локализовано**, публичного анализа нет |
| H. 112611/86950 (userland heap) | kernel-шаг | AIMED WRITE подтверждён; до root нужен kernel-шаг |

## 4. Честный итог

**Используемой дыры не найдено.** Пользовательская поверхность измерена и закрыта (кроме неопознанных 13 Mach-сервисов); kernel-класс даёт воспроизводимую паницу (112477, объект опознан) но не примитиву; единственный root-class CVE не локализован в образе. Дальше без устройства продвижение возможно только по двум пунктам: (D) имена 13 сервисов + их реверс в dyld-кэше из IPSW, и (G) targeted-поиск 32-битных timestamp по публичному XNU-диффа (нужен доступ к тегам после фикса).
