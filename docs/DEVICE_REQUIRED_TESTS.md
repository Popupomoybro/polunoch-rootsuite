# DEVICE_REQUIRED_TESTS.md — что можно проверить только на iPhone

> Устройство: iPhone13,1 / iOS 26.2 beta 1 (23C5027f). Сборка для всех тестов: **`RootSuite_panic_hunt.ipa`** (ветка `hunt-unit6`, run 45261728403, sha256 `3E491BA9…EE61`) — это рабочая база 22.11 + модули unit3/unit6 direct + без мёртвого KCE-свипа. Альтернатива для общего регресса: `RootSuite_working_2211.ipa`.
> Правило проекта: **ROOTSTATE NO** — единственный настоящий статус root. Ни один тест ниже не считается доказательством root без живого uid-0 probe.

## Минимум, который даёт максимум (для сеанса пользователя)

| # | модуль (тап) | повторов | что присылать | что узнаём |
|---|---|---|---|---|
| **D1** | `112477 V_BIG unit3 direct` | 5–8 | после каждого падения — .ips из Аналитики (Настройки → Конфиденциальность → Аналитика и улучшения → Данные аналитики → `panic-full-*` / `RootSuite-*`) | распределение вариантов: `far=8` (NULL) vs `far` в app-диапазоне; паницу с app-адресом = кандидат в контролируемое разыменование |
| **D2** | `112477 surface deref control` (P4) | 3–5 | .ips + **лог целиком** (Log → Share) — в логе карта «база поверхности → смещение → канарейка» | мостинг `far` паники ↔ карта поверхностей: если far попадает в наше отображение — ядро разыменовывает нашу память, и известно точно какое qword |
| **D3** | `112477 racer unit6 direct` | 2–3 | лог | контроль: рейсер уже 36 раундов чист; если появятся anomalies≠0 — stale-read без паники (это и есть оракул чтения) |

После каждого падения приложение открывается заново — в логе будет строка `previous launch died in unit N round M - advancing` (файл состояния переживает панику): она говорит, в каком именно раунде произошла паница.

## Что присылать (формат)

1. `.ips` файлы паник (каждый отдельно, имена сохранить).
2. `Log → Share` текстом (или скриншотами, если текстом неудобно) — с указанием, каким модулем и когда получен.
3. При любом `CRASH`/`SIGNAL` в логе — сразу (это регресс, чинится немедленно).

## Чего в этом списке нет и почему

* Проверка «root получен» без живого uid-0 probe — запрещена правилом проекта.
* Прогоны механизмов произвольной записи в ядро / подмены ucred — не разрабатываются по правилу проекта; фокус — диагностика и доказательная база.
* Тесты UI-редизайна (стекло) — после того как поэтапная сборка стекла пройдёт T1; сейчас база 22.11 является контролем.
