## 2. VERIFIED — механика паник 112477 (7 штук)

* **Маппинг:** `Kernel text exec base = __TEXT_EXEC.vmaddr (0xfffffff007fb8000) + KernelCache slide` — сверено точно на двух паниках с разными слайдами (0x11798000 / 0xc764000 / 0x10d94000 / 0x20060000). Файловое смещение инструкции сбоя = `0xfb4000 + 0x72418 = 0x1026418`.
* **Инструкция:** `casa x8, x9, [x0+8]` (файл 0x1026418) — атомарный CAS **с записью**: если `[x0+8]==0`, ядро пишет туда значение из текущего потока (`mrs x1,tpidr_el1; ldr w9,[x1,#0x440]`).
* **Семантика сбоя:** `far = x0 + 8`, `x0` = указатель блокировки, загруженный вызывающим кодом kext `com.apple.iokit.IOSurface 393.2.9` как `ldr x0, [x0, #0x148]` (поле объекта +0x148). Ранняя запись аудита «+0xd8» для данного кадра **неверна** — исправлено.
* **Путь:** `AGXG13P (341.11) → IOGPUFamily (129.2.10) → IOSurface (393.2.9) → ядро`. Код перед сбоем формирует panic-строку XNU `"Mutex to destroy still has waiters ... @lck_mtx_lock fast path (lock_mtx.c ~1053; the adjacent lck_mtx_destroy panic at lock_mtx.c:319 is NOT in the faulting path - correction per lock_analysis.md)"` — путь destroy/проверки мьютекса.
* **Варианты:** 6× `x0=0` (far=8, слот читается нулём), 1× `x0=0x7204459e8`-семейство (21.11, far = app-адрес+8, при churn поверхностей).
* **Воспроизводимость:** `112477 V_BIG unit3 direct` → паника за один запуск (device); `racer unit6 direct` ×4 = 36 раундов чисто (отрицательный результат: рейсер не вызывает дефект); `surface deref control` (P4) — вероятностный (1 паника в истории, 3 последних прогона чисты).
* **Канареек модуля в паниках нет** (проверка полными 64-битными значениями; ложный позитив `0x5151` = имя mach-порта в дампе потоков — устранён).

## 3. VERIFIED — проверка диversifier'а CVE-2026-65330 на нашем ядре

Публичный PoC утверждает: tmpfs `default_setxattr_doubleagent` подписывает указатель с **фиксированным диversifier'ом `#0x307a`** (проверено на 26.6/23G71). Проверка в нашем образе:

* Скан всего `__TEXT_EXEC` (26.9 МБ): `movz/movk any-reg, #0x307a` — **1 вхождение**, и оно **не PAC-контекст**: `mov w9, #0x307a` — номер строки в функции `handle_share_range` (APFS), рядом `0x3097`/`0x3080` (такие же номера строк), формат `"%s:%d: %s src (ino %llu) cannot be cloned\n"`.
* PACIA в образе есть (290 212 вхождений) — то есть PAC как механизм активен, но константы `0x307a` как диversifier'а в нашем ядре **нет**.

**Вывод:** применимость второй стадии публичной цепочки (65330) к 23C5027f — **UNVERIFIED** (нужен поиск `default_setxattr_doubleagent` в образе; версионно CVE затрагивает нашу сборку, но реализация/константа на 26.2b1 может отличаться).

## 4. VERIFIED — публичные методы и их совместимость (детали в ROOT_COMPATIBILITY.md)

* **CVE-2025-46285** — VERIFIED REAL (Apple iOS 26.2 security content, Kernel, «An app may be able to gain root privileges», исправлено 12.12.2025 в 26.2/18.7.3). Ядро 23C5027f собрано 28.10.2025 → **сборка должна быть уязвима**. Публичного PoC/анализа не найдено. Это **единственный CVE с описанием root** среди применимых.
* **CVE-2026-112477** — VERIFIED REAL (PoC github.com/Rust505/CVE-2026-112477, MIT, mode 407; исправлено в 26.7.2). Наш модуль — порт этого PoC с измерениями; мы пошли дальше публичного (локализация паники до инструкции).
* **CVE-2026-64788** — VERIFIED REAL (PoC ByteV0rtex/AmorCool, «tested on A14 Bionic, iPhone 12», исправлено 26.6.1). Zone sequestration блокирует r/w этим путём alone (согласно README PoC).
* **CVE-2026-112611 / 86950** — VERIFIED REAL (CoreGraphics; 86950 — в CISA KEV, эксплуатация в целевых атаках). У нас есть модули и AIMED WRITE CONFIRMED ×3 по 112611.
* **Джейлбрейки:** Dopamine 3.0.13 — A14 только до iOS 17.3.1 (iOS 26 = A12/A13); palera1n — A8–A11. **Публичного root для A14 на iOS 26.x нет.**

## 6. Честный итог

1. **Root на этой конфигурации не достигнут** и публичного пути к нему не существует (VERIFIED по тулам и CVE).
2. Наш 112477-слой — доказанная, воспроизводимая паника с полной локализацией; это диагностический результат, **не** UAF-доказательство и **не** root.
3. Самый перспективный применимый CVE по классу — **CVE-2025-46285** (root-LPE), но без публичного анализа это гипотеза.
4. Все промежуточные результаты названы своими именами: паника ≠ UAF; UAF ≠ controlled deref; controlled deref ≠ r/w; r/w ≠ root.
