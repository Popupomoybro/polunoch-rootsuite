# ROOT_ROADMAP.md — направления исследования root (iPhone13,1 / iOS 26.2b1)

> Обновлено 24.11.2026. Статус проекта: **ROOTSTATE NO**. Ниже — только доказательно обоснованные направления; каждый пункт содержит, что он даёт, что нужно, и чем может быть опровергнут.

> Обновлено 24.11.2026 (после веб-верификации). Ландшафт подтверждён: публичного root для A14 на iOS 26.x **нет** (Dopamine: A14 только до 17.3.1); единственный применимый CVE с описанием root — **CVE-2025-46285** (исправлен в 26.2 release, наша beta 1 предшествует фиксу); публичная цепочка 64788 -> kernel r/w -> 65330 -> PC control не завершается на iOS 26 из-за zone sequestration. Детали и ссылки: `RESEARCH_REPORT.md`, `ROOT_COMPATIBILITY.md`.

## Критерий успеха

`RootProbe()` возвращает YES (geteuid()==0 ИЛИ запись в root-owned путь). Всё остальное — промежуточные результаты: паника, stale-read, контролируемое разыменование, утечка адреса. Root ≠ эти вещи; в отчётах они называются своими именами.

---

## Приоритеты (переранжированы после веб-верификации)

1. **CVE-2025-46285 (root-LPE)** — единственный применимый CVE, чьё описание Apple прямо говорит «gain root privileges». Нужен публичный анализ/PoC или целевой реверс подсистемы с 32-битными timestamp (sandbox-extension expiry — первый кандидат: наш модуль `Sandbox: bad_query escape` уже даёт READ на /System).
2. **CVE-2026-64788 — порт публичного PoC в RootSuite** (диагностика): PoC тестирован на A14, не требует entitlements, даёт оракул `0xe00002c2 -> 0xe0002be`. Подтверждение/опровержение UAF на 23C5027f — измеримый результат без разработки цепочки.
3. **112477 — ловля APP-MAPPING варианта серией P4** (диагностика): контролируемое разыменование, не root.
4. **112611/86950 — userland OOB write** (диагностика): AIMED WRITE уже подтверждён в своей странице.
5. **65330 (PAC bypass)** — вторая стадия: применимость диversifier'а к 23C5027f не подтверждена (единственный `0x307a` в ядре — номер строки в `handle_share_range`).

## Направление 1 — 112477: от воспроизводимой паники к контролируемому разыменованию

**Что есть (VERIFIED):**
* Паника воспроизводима по команде: модуль `112477 V_BIG unit3 direct` даёт data-abort за один запуск.
* Локализация полная: `casa x8,x9,[x0+8]` (файл 0x1026418) в пути `lock_mtx.c:319`, вызывающий kext IOSurface 393.2.9, указатель блокировки из поля `[obj+0x148]`, `far = x0+8`.
* Распределение вариантов: 3× `x0=0` (far=8), 1× `x0=0x7204459e0` (far=app+8).
* Инструкция сбоя — **запись** по CAS: при валидном `[x0+8]==0` ядро пишет значение из текущего потока.

**Что даёт:** если слот освобождённого объекта удаётся заполнить контролируемыми данными (спрей правильного size-class), `far` становится нашим адресом → ядро либо читает, либо **пишет** по адресу, который мы выбираем смещением внутри своего отображения. Это не root, но это первая контролируемая примитива.

**Что нужно (device, см. DEVICE_REQUIRED_TESTS D1–D3):**
1. 5–8 паник unit3 direct — накопить статистику вариантов (все .ips).
2. 3–5 паник P4 с логами (карта поверхностей) — сопоставить `far` ↔ наше отображение.
3. Если `far` стабильно в app-диапазоне — перейти к прицельному спайву: подобрать size-class объекта (по канарейке, которая оказывается по `far`).

**Чем может быть опровергнут:**
* Все паники дают `x0=0` при 10+ повторах → слот занят внутренним объектом GPU-стека (путь AGXG13P→IOGPUFamily→IOSurface) или это teardown-гонка без UAF. Тогда направление закрывается как «паника есть, примитивы нет».
* Канарейки ни разу не попадают в `far` при десятках паник → спайв не попадает в size-class; без знания размера класса (символов нет) подбор слепой.

**Вероятность получения контролируемого разыменования (честно):** moderate-low до получения серии паник с app-адресом; оценим после D1–D2.

## Направление 2 — CVE-2025-46285 (root-LPE, первая по статике)

**Что есть:** публичное описание Apple: «An integer overflow was addressed by adopting 64-bit timestamps. An app may be able to gain root privileges.» Исправлено в iOS 26.2 / 18.7.3 (12.12.2025). Ядро 23C5027f собрано 28.10.2025 — **раньше фикса**, то есть сборка должна быть уязвимой.

**Что даёт:** потенциально прямой root-LPE (единственное направление, где исходный дефект описан как дающий root).

**Что нужно:**
1. Подтвердить по security-release-нотам Apple точную дату фикса и затронутые подсистемы (веб-ресёрч выполняется).
2. Найти публичный анализ/PoC (если существует) — что именно переполняется (sandbox-extension expiry? kauth cred timestamps? vnode/ACL?).
3. Device: воспроизведение сценария из публичного анализа, затем RootProbe.

**Чем может быть опровергнут:** в 26.2b1 фикс уже присутствует (b1 мог собраться позже описания); либо публичного анализа нет и воспроизведение вслепую нереалистично; либо вектор требует условий, недостижимых из sandboxed-приложения.

## Направление 3 — IOGPUFamily UAF (CVE-2026-64788, публичный PoC заявлен)

**Что есть (требует веб-проверки):** заявлен публичный PoC под A14 (`create_resource_iosurface`, set_resource_purgeable, stale-entry), фикс в 26.6.1. Паника 23.11 имеет в backtrace именно `IOGPUFamily (129.2.10)` + `AGXG13P` — путь GPU-стека реален.

**Что даёт:** kernel memory corruption → потенциально r/w.

**Что нужно:** верификация существования PoC (субагент); если реален — порт под 23C5027f (без Metal-доступа в этой сборке RootSuite нужно проверять, какие API доступны sandboxed-приложению).

**Чем может быть опровергнут:** PoC не существует/не для A14; zone sequestration на iOS 26 делает reclaimed-слот type-stable и нерелевантным для sprayed-объектов.

---

## Направление 4 — tmpfs PAC diversifier bypass (CVE-2026-65330)

**Что есть (требует веб-проверки):** заявлен обход PAC-диversifier в tmpfs VNOP setxattr, фикс в 26.6.1 и в 26.2b1 — то есть наша сборка могла уже содержать фикс.

**Чем может быть опровергнут:** фикс в 26.2b1 присутствует (тогда вектор мёртв для 23C5027f).

---

## Направление 5 — CoreGraphics Type-5 shading (CVE-2026-112611) и ImageIO (CVE-2026-86950)

**Что есть:** в RootSuite уже есть модули (`112611 force write` — AIMED WRITE CONFIRMED ×3 в своей странице; `86950` — гард поймал полную запись). Это userland-heap векторы.

**Что даёт:** userland R/W; для root нужен ещё kernel-шаг (по правилу проекта цепочку не строим — фиксируем как диагностические направления).
