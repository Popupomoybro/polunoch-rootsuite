# DESIGN_SYSTEM.md — дизайн-система RootSuite

> Состояние на 24.11.2026. Документ описывает **и рабочую базy (22.11 UI)**, и целевое направление (Liquid Glass), с честной фиксацией, что есть на диске, а что — план.

## 1. Принципы

1. **Правда превыше оформления.** ROOTSTATE — только живой probe; проценты готовности, прогресс-бары «ради красоты», декоративные элементы запрещены.
2. **Телефон — первичный носитель данных.** Лог, вердикты, состояние паник-охоты читаются на устройстве без ПК.
3. **Одна ясная иерархия:** статус → действие → доказательство (лог).
4. **Стекло — умеренно.** Материал как подсветка иерархии, не как самоцель.

## 2. Что работает сейчас (база 22.11, IPA на десктопе)

| экран | состав |
|---|---|
| Главный (модули) | ROOT-пилюля (живой статус), список модулей-карточек (имя, описание, галочка выбора), Run / Run root chain |
| Log (RSTextVC) | полноэкранный лог: Share / Copy / Close, авто-скролл, моноширинный шрифт |
| Установщики | Sileo / Terminal (появляются при root) |
| Forensic | файл `rs112477.log`, читается обратно в Log при старте (краш/паника не убивает историю) |

Тёмная тема — единственная (базовая). Светлая — цель редизайна.

## 3. Целевое направление (Liquid Glass, iOS 26)

Иерархия экранов (5 табов — как в `master`, но поверх рабочей базы):

1. **Dashboard** — статус проекта: ROOTSTATE pill (живой), устройство/сборка, последние события (из forensic-файла), кнопка цепочки, лог-строка.
2. **Exploit Research** — таблица модулей по статусам (PROVEN / PUBLIC / KERNEL / ROOT2K), выбор, прогон, вердикты.
3. **Kernel Diagnostics** — идентичность образа (UUID, slide, kext-версии), механика подтверждённых паник, хвост лога.
4. **Research History** — датированные находки со статусами (VERIFIED / EXPERIMENTAL / HYPOTHESIS / FAILED).
5. **Settings** — endpoint миррора, AUTO env, forensic-файл, Refresh ROOTSTATE, о приложении.

Токены (из `RSGlass.m`, проверенный набор):

| токен | значение |
|---|---|
| canvas | `#090A0E`-глубина (rgb 0.035/0.039/0.055) |
| ink / ink2 / ink3 | 0.98 / 0.72 / 0.48 белый |
| accent | rgb(0.38, 0.55, 1.00) |
| good / warn / bad | rgb(0.20,0.85,0.45) / (1.00,0.72,0.25) / (1.00,0.32,0.38) |
| карточка | fill white 5.5%, radius 22–28, `cornerCurve` continuous, border white 16% 0.6pt, specular-градиент 22%→0 (30% высоты), тень black 45% r18 y8 |
| бар (nav/tab) | `UIBlurEffect systemChromeMaterial` — **только UIBlurEffect** (UIGlassEffect в `backgroundEffect` = краш UIKit, зафиксировано) |
| своя панель | `UIGlassEffect` **только внутри** `UIVisualEffectView` через `initWithStyle:0` |
| движение | springs damping 0.55–0.9; press scale 0.965 |

## 4. Правила, добытые крашами (обязательны к соблюдению)

1. `UIGlassEffect` никогда не назначается в `backgroundEffect` (тип `UIBlurEffect *`) — первый краш стекла.
2. Off-screen `UITextView` как хранилище лога запрещён — TextKit перестраивал attributed-string на каждую строку (цепочка .ips: `initWithString: → NSRLEArray → malloc freelist brk 1`). Хранилище — строка.
3. Периодические таймеры, трогающие TextKit-вью, — не чаще 5с и с капом символов (3000) и проверкой изменений.
4. Follow-таймер лог-окна: 1.5с + пропуск при неизменившемся тексте.
5. POST-миррор: отдельная ephemeral-сессия, max 2/host, 2с, кап pending 64 — отстаёт, но не растёт бесконечно.
